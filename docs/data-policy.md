# 식재료·필터·제보 정책

기준: [PRD](https://docs.google.com/document/d/1mKtalKrWTfE0ME1OB4wfT6ntDxUADFulkBatFlnQEnU/edit) 및 [기능정의서 v1.1.0](https://docs.google.com/spreadsheets/d/1gz_mPcyv0wkcNCSgEGfBRO6cN5kmBx0osrvvxVq84Rk/edit), 2026-11-20 확인. 상세 예외·문구는 해당 기능 행을 확인한다.

## 식재료와 필터

- 메뉴마다 돼지고기·소고기·닭고기·기타 고기·해산물·계란·유제품 7개 항목을 각각 포함·미포함·미확인으로 저장한다. 자료가 없으면 미확인이며 미포함과 다른 값이다. 항목별 마지막 확인일과 확인 방법도 기록한다.
- 필터는 돼지고기 없음·소고기 없음·고기 없음·해산물 없음·계란 없음·유제품 없음이다. 고기 없음은 돼지고기·소고기·닭고기·기타 고기가 모두 미포함일 때 충족한다.
- 선택한 태그에 필요한 항목이 모두 미포함인 메뉴만 충족한다. 관련 항목에 포함 또는 미확인이 있으면 미충족이다. 한 메뉴가 선택한 모든 태그를 동시에 충족해야 하며, 이런 메뉴가 하나 이상인 식당만 필터 결과에 포함한다. 서로 다른 메뉴가 조건을 나눠 충족하면 제외한다.
- 예: 메뉴 A는 고기 없음만, 메뉴 B는 해산물 없음만 충족하면 두 태그를 함께 선택한 결과에 해당 식당을 포함하지 않는다.
- 지도와 목록은 같은 검색·필터·위치 기준을 사용한다. 좌표 없는 식당은 목록에서 위치 정보 미제공으로 표시하고 지도에는 표시하지 않는다.
- 메뉴명·사진에서 식재료를 추론하지 않는다. 비건·할랄 인증 또는 알레르기 안전 여부를 대신 판정하지 않는다.

## 검색·정렬·언어

- 식당/메뉴 검색 모드를 구분하고 한글·영문명을 모두 검색한다. 한글은 자음·모음 단위, 영문은 대소문자 구분 없이 판별한다. 좌측부터 일치하는 정도를 우선하고 동률이면 남은 부분의 가나다순을 적용한다. 필터가 있으면 그 범위 안에서 검색한다. 공백만 입력하면 빈 검색어로 처리하고 검색 식당 목록을 표시하지 않는다(CHK-01).
- 일반 탐색에서 검색·태그가 모두 없으면 전체 등록 대상 식당을 거리순으로 표시한다. 검색 또는 태그가 있으면 기본 일치도순이며, 검색은 검색어 일치도, 태그만 있으면 모든 선택 태그를 충족하는 메뉴 수를 사용한다. 동률은 거리순이다. 거리순 선택도 제공한다. 연속 요청은 최신 검색어의 결과만 반영한다.
- 위치 조회 실패·거부 시 서울대학교 인문대학 1동을 기준으로 사용하고 현재 위치 파란 점은 표시하지 않는다. 초기 지도는 캠퍼스 전체를 보여준다. 지도 API 요청은 최초 포함 총 3회까지만 시도한다. 이는 런타임 요청 횟수이며 개발 중 수정·재검증 2회 상한과 별개다.
- 지도 대표 태그는 충족 메뉴 수가 가장 많은 태그이며 동률이면 화면 태그 순서, 없으면 회색이다.
- 식당 메뉴 목록은 필터와 관계없이 전체 메뉴를 표시한다. 기본은 충족 태그 수 내림차순·동률 가나다순이며, 필터 적용 시 모든 선택 태그 충족 메뉴를 우선한다.
- 한국어·영어 UI 문구를 미리 작성한다. 기본은 브라우저 언어가 한국어이면 한국어, 그 밖에는 영어다. 선택 언어는 브라우저에 저장한다. 영문명 없으면 한글명으로 표시하고 자동 번역하지 않는다.

## 계정·제보·운영진

- 조회는 로그인 없이 가능하고 제보·신고는 로그인 후 가능하다. 공개 회원가입은 정규화한 아이디로 학생 계정을 만든다. 서버가 부여한 app_metadata.role로 제보 승인·반려 권한을 판정한다. 로그인 후 직전 화면으로 복귀하며 로그인 상태를 유지한다. 운영진 권한은 Supabase Auth의 사용자 역할로 구분한다.
- 모든 제보는 공개 정보와 별도로 검토 대기 상태에 저장하고 제보자 ID·제출 일시를 기록한다. 제보 내용만으로 공개 정보나 필터를 바꾸지 않는다.
- 기존 정보 수정은 현재 공개 값을 기본값으로 표시하고 변경 항목만 저장한다. 확인 방법은 ‘직원 확인’, ‘메뉴판·성분표’, ‘직접 확인’ 세 가지 중 선택하며 필수다.
- 새 메뉴는 대상 식당과 한글 메뉴명이 필수이며 사진·영문명·식재료 입력은 선택이다. 미입력 식재료는 미확인으로 저장하고 하나라도 입력하면 확인 방법이 필수다. 사진 업로드 실패 시 사진 없이 제출할 수 있다. 공백 제거 후 같은 식당 내 완전히 같은 메뉴명은 기존 메뉴 수정으로 안내한다.
- 새 식당은 이름과 지도 위치가 필수다. 학내 밖 위치는 거부하고, 반경 50m 내 같은 이름의 식당이 있으면 기존 식당 상세로 안내한다.
- 사진은 Supabase Storage에 저장하고 승인 전 비공개로 둔다. 제출 실패 시 입력을 유지한다.
- 운영진만 관리자 페이지에서 제보와 현재 정보를 비교하고 처리한다. 대기 목록 기본 정렬은 오래된 제출 순이며 유형·상태 필터를 제공한다. 이미 처리됐거나 다른 운영진이 먼저 처리한 제보의 중복 처리를 막는다.
- 승인 시 일부 항목을 선택할 수 있다. 상충하는 값은 확인 방법 우선순위(직원 확인 > 메뉴판·성분표 > 직접 확인)를 적용하고 같으면 최신 제보를 우선한다. 처리자·처리 일시를 기록한다.
- 반려 사유는 근거 부족·중복 제보·기존 정보와 동일·부적절한 내용·기타(직접 입력)이며 반려는 공개 정보에 영향을 주지 않는다.
- 승인 반영 시 식재료 값과 확인일·방법, 메뉴 상세·필터·지도를 갱신한다. 공개 정보 변경과 제보 상태 변경은 한 트랜잭션으로 처리한다. 폐점·판매 종료 승인 시 데이터는 보존하고 공개 목록에서 숨긴다.
- 내 제보는 최신순으로 유형·대상·제출 일시·상태·반려 사유를 보여준다. 내 식이 정보와 찜은 MVP에서 제외한다.

## 원문 확인이 필요한 경계

- INP-07은 반영 실패 상태와 재시도를 요구하지만 운영진 필터·내 제보 목록은 검토 대기/승인/반려만 열거한다. 부분 승인 후 나머지 항목의 상태와 함께, 화면별 상태 매핑 및 실패 기록을 어디에 둘지 구현 전에 확인한다. 공개 정보와 제보 상태의 원자적 변경 원칙은 유지한다.
- CHK-01의 빈 검색 목록과 CHK-03의 조건 없는 전체 탐색은 서로 다른 상태로 명시돼 있다. 검색어를 지웠을 때 어느 상태로 이동하는지는 구현 전에 확인한다.
- 식당과 메뉴의 검색 일치도 계산 세부값, 위치·거리 계산에 필요한 기본 좌표, 학내 경계와 태그 표시 순서는 원문에 수치가 없으므로 임의로 확정하지 않는다.
