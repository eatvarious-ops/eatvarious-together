# 검증 기준

AI가 작업별 완료 기준과 실제 결과를 관리한다. [작업 목록](tasks.md)의 번호와 일치시킨다. 실행 결과는 PR에 확인 방법·예상 결과·관찰한 결과·판정(통과/실패/미실행)으로 남긴다.

기능 작업은 [개발 품질 규칙](development.md)에 따라 해당 영역의 정상·경계·오류 상황과 영향받는 기존 동작을 확인한다. 문서 작업은 내용의 일관성, 로컬 링크, 사용자 요청 충족 여부를 확인한다. 검사 실패나 미실행이 있으면 이유를 적고 완료로 표시하지 않는다. 실제 적용된 자동 검사와 권한 설정은 개발 품질 문서에서 확인한다.

## 1 · 팀 하네스 구성

- README와 첫 작업 안내의 시작 요청이 “팀 규칙대로 [맡은 일] 작업해 줘”로 같고, 단계별 추가 요청 없이 AI가 작업 등록 확인·구현·검사·셀프리뷰·PR 준비를 이어 가도록 안내한다.
- AI 지침에서 자료 접근 실패, 미정 정책, 기존 변경 보존, 작업 영역 구분, 요청 밖 구현 금지, 승인 전 병합 금지를 확인할 수 있다.
- 개발 규칙에 백엔드의 임의 UI 제작 금지, 프론트엔드의 임의 API·데이터 규칙 변경 금지, 영역별 검증과 실제 연결 여부 기록이 있다.
- PR 양식에서 작업 번호, 영역, 범위, 검증 결과, 미확인 항목을 기록할 수 있다.
- 실수 기록과 반복 실패 시 인계 절차가 연결돼 있고, 실제 설정된 장치와 향후 적용할 장치를 구분한다.
- README에서 팀 문서와 Drive 자료를 찾을 수 있고 로컬 링크가 유효하다. 외부 자료 접근은 별도 결과로 기록한다.

## 2 · 최신 PRD·기능정의서와 저장소 문서 동기화

- 기능정의서 v1.1.0의 CHK-01~08, INP-01~09, MY-01~09 ID·이름·우선순위가 기능 색인과 일치한다.
- 식재료 7종, 필터 6종, 동일 메뉴의 복수 태그 충족, 관련 항목 미확인 시 미충족 규칙이 정책에 반영돼 있다.
- 구글 로그인·내 제보·운영진 처리의 포함과 내 식이 정보·찜·알레르기 정보의 제외가 구분된다.
- 검색·지도·제보·언어 정책과 원문 간 미확정 경계를 기록하고, 원문 링크 및 로컬 문서 링크를 확인한다.
- 문서 동기화를 실제 기능 구현·자동 검사 적용 완료로 표시하지 않는다.

## 9 · 새 메뉴의 고기 입력

- 새 메뉴에서 여러 고기를 선택하거나 해제하고 미확인·고기 없음으로 전환한다. 해산물·계란·유제품과 기존 메뉴 수정 입력을 확인한다.
- 승인 후 선택한 종류만 포함인지, 고기 없음은 네 종류 모두 미포함인지 확인한다. 종류 모름은 확인 방법을 요구하고 원래 메모와 함께 접수한다.

## 새 작업에 추가할 내용

AI가 작업 번호와 이름, 확인할 동작, 정상·대표 예외 조건, 예상 결과, 검증 방법을 작성한다. API 연결이 필요하면 상대 영역과 실제로 연결했는지도 별도 확인한다. 문서만으로 확인할 수 없는 동작은 실제 실행 전까지 통과로 표시하지 않는다.

## 3 · 실행 및 검사 환경

- 영역별 설치와 실행 명령을 재현하고 PR의 자동 검사 실행 여부를 확인한다.
- 일반 PR 검사에 운영 비밀·데이터가 필요 없는지, 파일 리뷰 대상과 실제 쓰기·병합 제한이 어떻게 적용되는지 확인한다.

## 4 · 제보 저장과 운영진 검토 백엔드

- 실제 setup.sql을 격리된 PostgreSQL에서 두 번 실행한다. 익명·일반 회원·운영진 권한을 각각 검사한다.
- 중복·경계 밖 요청, 부분 승인, 상충 우선순위, 반려, 이미 처리된 제보, 실패 후 재시도와 사진 공개 전환을 검사한다.

## 5 · 식당 탐색과 제보 웹 화면

- 식당·메뉴 검색, 같은 메뉴에서 충족해야 하는 복수 필터, 지도·목록 동기화, 빈 결과와 언어 전환을 확인한다.
- 로그인 직전 제보 복귀, 확인 방법 선택, 승인 전후 공개 메뉴 수 변화와 내 제보 상태를 확인한다.
- 모바일과 데스크톱 화면의 조작을 확인하고 Figma 대조와 실제 OAuth·지도·저장소 연결 결과를 구분한다.

## 6 · Google 로그인 (MY-02)

- 비로그인 식당 조회와 제보 시작 시 로그인 안내를 확인한다.
- 개발 Supabase에서 최초 Google 로그인, 제보 양식 복귀, 새로고침 후 세션 유지, 로그아웃과 일반 회원의 운영진 접근 제한을 확인한다.
- Google 로그인 취소·오류 뒤 원래 화면에서 재시도할 수 있는지 확인한다.

## 6 · 실제 캠퍼스 지도 연결

- 키 없는 HTTP 실행에서 관악캠퍼스 온라인 타일과 출처 표시를 확인한다. 파일 실행과 타일 요청 실패 때 저장된 실제 지도가 표시되어야 한다.
- 모바일·PC에서 확대, 검색·필터 후 핀 개수, 식당 상세 진입, 새 식당 좌표 지정을 확인한다.
- NAVER 공개 Client ID와 허용 웹 주소, 파일 실행의 차이를 문서화하고 실제 인증 검증 여부를 기록한다.

## 7 · 체험용 잇다.html 미리보기 공유

- preview/잇다.html이 기록한 브랜치·커밋의 `npm run build` 결과(frontend/dist/index.html)와 같다.
- preview/README.md에 출처 커밋, 포함된 공개 설정(NAVER Client ID), 실행 방법, 체험 모드 한계가 적혀 있다.
- 비밀값(Client Secret·서비스 키)이 포함되지 않았다.

## 8 · 지도 작업 main 반영과 preview 제거

- main의 frontend에서 `npm test`가 통과하고 기본 빌드(`npm run build`)에 NAVER 공개 Client ID가 포함된다.
- Google 로그인(작업 6)과 지도(작업 6) 변경이 함께 유지된다.
- preview/가 삭제되고, 병합 후 Vercel 배포(https://itda-snu.vercel.app)가 main의 frontend 빌드로 NAVER 지도를 표시한다.

## 10 · 학생 계정 발급과 제보 권한

- 가입 권한·중복·가입 횟수 제한과 학생 제보 및 운영진 검토를 검증한다.
