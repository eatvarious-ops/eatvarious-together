# 검증 기준

각 항목은 같은 번호의 [작업](tasks.md)을 검토할 때 다시 사용하는 기준이다. 확인 결과는 PR 본문에 번호·확인 방법·관찰한 결과 순서로 남긴다.

기능 작업에는 [개발 품질 규칙](development.md)의 해당 영역 검증을 적용한다. 요청 충족 여부, 영역 경계, 요청 밖 변경 유무, API 약속, 실제 연결 여부를 검토한다. 자동 검사와 권한 설정의 실제 적용 상태도 해당 문서에서 확인한다.

작업 1의 시작 요청은 “팀 규칙대로 [맡은 일] 작업해 줘” 한 문장이다. README와 첫 작업 안내의 요청이 같고, AGENTS.md가 작업 등록 확인부터 구현·검사·셀프리뷰·PR 준비까지 추가 요청 없이 이어 가도록 지시하는지 확인한다. 미정 정책과 권한이 필요한 경우에는 필요한 결정만 묻도록 한다.

- [ ] 1. README에서 프로젝트 참고 자료와 팀 문서, 첫 작업 안내, 병합 승인자를 찾을 수 있다. 첫 작업 안내를 따라 작업 선택부터 결과 확인과 PR 제출까지 진행할 수 있다. AI 작업 지침에 범위 확인, 기존 변경 보존, 실제 검증, 미확인 항목 보고, 승인 전 병합 금지가 적혀 있다. PR 양식에서 작업 번호와 검증 결과를 기록할 수 있다.
