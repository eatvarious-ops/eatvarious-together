# 처음 작업하는 팀원을 위한 안내

코드를 읽거나 명령어를 외울 필요는 없습니다. AI에게 맡은 일을 평소 말로 설명하고, AI가 보여 주는 작업 범위와 실제 결과를 직접 확인하세요. 모르는 용어가 나오면 "쉬운 말로 설명해 줘"라고 요청하세요.

## 0. 시작 준비

팀의 GitHub 저장소와 [설계 자료 폴더](https://drive.google.com/drive/folders/1dQFtCVjYneL9wQ7B_lJL9zVF24d1OhKj)를 열 수 있는지 확인합니다. AI 코딩 도구에서 저장소 폴더를 열어 주세요. 아직 컴퓨터에 저장소가 없다면 [GitHub 저장소](https://github.com/eatvarious-ops/eatvarious-together)를 내려받아 연 뒤 AI 도구에서 그 폴더를 선택합니다. 어디서 시작해야 할지 모르겠다면 AI에게 "이 저장소를 열고 작업을 시작할 수 있게 단계별로 안내해 줘"라고 요청하세요.

AI가 `README.md`와 `AGENTS.md`를 읽을 수 있는지 먼저 확인합니다. Drive 자료나 GitHub 저장소에 접근할 수 없다면 팀에 권한을 요청합니다.

## 1. 맡은 일 확인

1. [작업 목록](tasks.md)에서 맡은 일을 찾습니다. 작업 번호를 몰라도 작업 내용을 말하면 AI가 찾아야 합니다.
2. [검증 기준](checklist.md)에서 같은 번호의 완료 기준을 확인합니다. 기능 구현은 팀이 확정한 기능정의서 항목과 연결되어야 합니다.
3. 작업이 목록에 없거나 완료 기준이 없으면 AI에게 [작업 카드 양식](task-card-template.md)으로 초안을 만들게 하고, 팀과 범위를 정한 뒤 개발합니다.

AI에게 보낼 첫 요청:

> 이 저장소의 README, AGENTS.md, 관련 Drive 자료, 작업 목록, 검증 기준을 읽어 줘. 내가 맡은 일은 [작업 내용]이야. 해당 작업 번호와 완료 기준, 바꿀 파일, 아직 팀 결정이 필요한 내용을 쉬운 말로 먼저 알려 줘. 기존 수정 사항은 보존하고, 범위가 확실한 부분부터 구현해 줘.

## 2. AI와 구현하기

AI가 작업용 브랜치에서 한 작업만 수정하도록 합니다. 진행 중에는 "지금 무엇을 바꿨고 남은 일은 무엇이야?"라고 물어볼 수 있습니다. 정책이 정해지지 않았거나 다른 팀원의 파일과 겹치면 임의로 결정하지 말고 팀에 확인합니다.

비밀키, 토큰, 실제 사용자 정보는 채팅에 붙여 넣거나 저장소에 올리지 않습니다. 메뉴명과 사진만 보고 식재료를 추측하지 않습니다. 운영 데이터 변경이나 배포가 필요한 경우에는 먼저 영향과 승인 범위를 확인합니다.

## 3. 결과 직접 확인하기

AI에게 다음처럼 요청합니다.

> 완료 기준을 하나씩 직접 확인해 줘. 앱을 실행할 수 있으면 내가 볼 수 있게 열고, 정상 흐름과 빈 값·오류 상황을 확인해 줘. 실행한 검사와 실제 결과, 확인하지 못한 항목을 나눠서 알려 줘. 변경한 파일도 쉬운 말로 설명해 줘.

화면을 볼 수 있으면 본인이 직접 눌러 보고 예상한 결과가 나오는지 확인합니다. 마음에 들지 않거나 오류가 보이면 그대로 AI에게 말하고 고치게 합니다. 앱 실행 방법이 README에 아직 없으면 AI가 확인하지 못했다고 적어야 합니다.

## 4. PR로 제출하기

PR은 변경 사항을 `main`에 합치기 전에 팀원이 검토하는 요청입니다. AI에게 다음처럼 요청합니다.

> 변경 파일을 다시 확인하고, 맡은 작업 하나만 담긴 PR을 준비해 줘. PR 양식에 작업 번호, 바꾼 이유, 확인 방법과 실제 결과, 확인하지 못한 항목을 적어 줘. 리뷰 대상은 @Eun-Y0ung이야. 승인 전에는 병합하지 마.

PR에서 바뀐 내용과 확인 결과를 읽고, 화면이 있다면 직접 확인한 뒤 리뷰를 요청합니다. 성은영의 승인 후에만 병합합니다. 성은영이 직접 작업한 경우에는 다른 팀원이 변경 내용을 확인하고 PR 작성자를 맡습니다.

## 막혔을 때

- Drive 자료를 열 수 없으면 접근 실패 사실을 알리고, 확인하지 못한 내용을 추측하지 않습니다.
- 검사에 실패하면 실패한 조건과 관찰한 결과를 남기고 고칩니다. 해결하지 못하면 PR에 그대로 적습니다.
- 맡은 일 밖의 기능이 필요해 보이면 이번 PR에 몰래 넣지 말고 새 작업으로 제안합니다.
