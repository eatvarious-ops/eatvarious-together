# 처음 작업하는 팀원을 위한 안내

AI 코딩 도구에서 팀 저장소 폴더를 열고 아래 한 문장만 보내세요.

> 팀 규칙대로 [맡은 일] 작업해 줘.

예: “팀 규칙대로 식당 및 메뉴 검색 작업해 줘.” 작업 번호나 파일 이름, 실행 명령을 알 필요는 없습니다.

## AI가 이어서 하는 일

1. 팀 문서와 Drive의 기능정의서를 읽고 맡은 일과 완료 기준을 찾습니다. 빠진 작업 등록과 검증 기준 작성도 AI가 처리합니다.
2. 맡은 일이 서버·데이터 작업인지 화면 작업인지 구분하고 기존 수정 사항을 보존해 구현합니다. 요청하지 않은 화면이나 기능은 추가하지 않습니다. 작업 영역이나 정책이 불명확할 때만 필요한 선택을 쉽게 설명하고 질문합니다.
3. 실행 방법을 찾아 직접 검사하고, 화면 변경은 실제 화면도 확인합니다. 변경 내용을 스스로 검토하고 발견한 문제를 고칩니다.
4. 사용자가 볼 결과와 확인 순서를 보여 주고, 작업 내용과 검사 결과를 담은 PR을 준비·제출합니다. PR은 팀원이 변경 사항을 검토하는 요청입니다. 검사가 실패하거나 실행되지 못했으면 그 사실과 필요한 조치를 알리고 완료로 표시하지 않습니다.

각 단계마다 새로 지시하지 않아도 됩니다. AI가 결정을 물으면 답하고, 결과가 나오면 안내에 따라 직접 확인하세요. 원하는 동작과 다르면 “이렇게 바꿔 줘”라고 평소 말로 설명하면 됩니다.

성은영(@Eun-Y0ung)의 승인 후에만 병합합니다. 성은영이 작업에 참여한 경우 다른 팀원이 변경 내용을 확인하고 PR 작성자를 맡습니다. 이때 AI는 브랜치와 PR 본문을 준비해 넘깁니다.

## 처음 한 번 필요한 준비

AI 도구에서 이 저장소를 열 수 있어야 하고, 작업 계정에 GitHub 저장소와 Drive 설계 자료를 읽을 권한이 있어야 합니다. 저장소를 처음 여는 방법을 모르겠다면 팀에 작업 환경 연결을 요청하세요. 이후에는 위 한 문장으로 시작할 수 있습니다.

GitHub 로그인이나 Drive 접근이 막히면 AI가 필요한 연결 방법을 안내합니다. 비밀키·토큰은 채팅에 붙이지 말고 도구의 로그인 또는 환경 설정으로 연결하세요. 현재 저장소에는 앱 코드가 없어 첫 기능 개발 전에 앱 환경 구성 작업이 필요합니다.
