# 캠퍼스 식당 웹앱

Node.js 24에서 이 디렉터리의 `npm ci`, `npm test`, `npm start`를 차례로 실행한다. 테스트는 먼저 프로덕션 HTML을 빌드한다. http://127.0.0.1:4173 을 열거나 생성된 `dist/index.html`을 Chrome에서 연다. 빌드만 하려면 `npm run build`를 사용한다.

기본 체험 모드는 가상 식당 6곳과 메뉴 14개, 오프라인 캠퍼스 약도를 사용한다. 식당에서 메뉴를 열어 7개 재료 상태를 보고 학생으로 추가 제보한다. 운영진 체험 계정에서 승인·반려하고, 공개 메뉴와 학생의 내 제보에서 결과를 확인한다. 사진 출처는 src/seed.js에 기록했다. 체험 데이터는 실제 식사 판단에 사용하지 않는다.

개발 서비스에 연결하려면 빌드 환경에 ITDA_SUPABASE_URL과 ITDA_SUPABASE_PUBLIC_KEY를 함께 지정한다. Google OAuth 리디렉션 주소에 로컬 주소를 등록한다. 실제 지도를 쓰려면 같은 주소를 NAVER Cloud에 등록하고 ITDA_NAVER_CLIENT_ID를 지정한다. 이 세 값은 모두 브라우저에 포함되는 공개용 설정이다. 비밀 키를 입력하지 않는다.

## Google 로그인 확인

개발 Supabase 프로젝트에서 Google 제공자를 설정하고, Supabase가 표시하는 콜백 URL을 Google OAuth 클라이언트의 승인된 리디렉션 URI에 추가한다. Supabase Auth의 허용 리디렉션 URL에는 앱이 실행되는 주소(예: `http://127.0.0.1:4173/`)를 등록한다.

1. 로그아웃 상태에서 식당과 메뉴를 열 수 있는지 확인한다.
2. 메뉴 상세에서 제보를 시작하고 Google 로그인을 완료한다. 제보 양식으로 돌아오고, 새로고침해도 계정 상태가 유지되는지 확인한다.
3. 로그아웃한 뒤 다시 제보를 시작한다. Google 로그인 취소나 실패 시 원래 상세 화면으로 돌아와 재시도할 수 있는지 확인한다.
4. 일반 Google 계정이 운영진 메뉴에 접근할 수 없는지 확인한다.
